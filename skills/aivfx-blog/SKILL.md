# aivfx-blog: статья от темы до замера

## Зачем

Блог маленькой студии живёт на нескольких десятках статей, и каждая
должна отвечать на вопрос, который люди правда задают. Главные потери
времени были одни и те же: тема из головы, картинка до согласования,
факт по памяти, тихая проверка, выкат без слова владельца. Скилл держит
порядок этапов, правила текста и три проверялки, чтобы эти ошибки
ловились машиной, а не читателем.

## На чём работает

| Инструмент | Зачем здесь | Кто делает |
|---|---|---|
| Google Search Console | запросы, страницы и страны, по которым сайт уже показывается; запрос индексации нового адреса | владелец даёт доступ, агент смотрит через его браузер |
| Яндекс Вебмастер | то же для Яндекса: кластеры на позициях 6-15 без кликов | владелец даёт доступ, агент смотрит |
| Живые вопросы людей | сообщества, комментарии, чаты, вопросы из заявок; база вопросов в таблице или Notion (или аналог) | агент собирает, владелец решает, что брать |
| Поисковые подсказки | формулировки для заголовков и FAQ, `scripts/suggest.py` | агент |
| Вордстат | частотность, дополнительный источник, только из аккаунта владельца | владелец или агент в его браузере |
| Claude Code (или аналог) | дирижёр и субагенты: синопсис, факты, текст, проверки, вставка в данные сайта | агент, ревью дирижёра |
| `aivfx-cover`, `aivfx-look` | обложка: генерация в Seedream 5 Pro или Nano Banana через Higgsfield (или аналог) с фирменным луком | агент генерирует, владелец выбирает |
| Репозиторий сайта | статьи лежат файлами данных; у студии это React с пререндером в статику, у тебя может быть markdown, json или CMS | агент правит, коммит локально |
| Хостинг и `DEPLOY-QUEUE.md` | выкат пачкой из репозитория | только по слову владельца |
| IndexNow | одним запросом сообщить Bing и Яндексу новые и обновлённые адреса | агент после выката |
| `aivfx-track` | Метрика с целями, переходник `/go/` с журналом, недельный отчёт | агент, цифры только из панелей |
| Python 3 | скрипты в `scripts/`, только стандартная библиотека | агент |

## Когда включать

- Новая статья, гайд или волна из нескольких статей.
- Обновление старой статьи или её языковой версии.
- Проверка готового текста: структура, язык, свежесть.
- Ежемесячная ревизия блога на протухшие факты.

Посты для соцсетей ведёт `aivfx-social`, не этот скилл.

## Этапы

### 1. Тема из спроса и вопросов

Тема из головы почти всегда пишется в пустоту. Так было на сайте студии:
отраслевые страницы «ИИ для бизнеса такого-то» писались месяцами, а
запросов под них почти не было, зато вокруг самих инструментов спрос в
сотни раз больше.

Порядок источников:
1. **Search Console и Вебмастер.** Кластеры, где сайт уже показывается на
   позициях 6-15 с нулём кликов: странице не хватает точности под
   формулировки, а не объёма. Смотри страны: язык страницы не равен
   аудитории. Панели отстают на несколько дней, по последним дням выводов
   не делай.
2. **Живые вопросы.** Записывай дословно, как спросил человек: это готовый
   заголовок раздела или пункт FAQ. Если площадка закрыта для агента, не
   трать больше пары попыток.
3. **Подсказки** (`scripts/suggest.py`) дают формулировки без цифр.
4. **Вордстат** по главным формулировкам, если есть доступ. Цифры только
   из аккаунта владельца, с датой и регионом. Нет доступа: «частотность не
   знаю», а не оценка на глаз.

Раздели запросы на транзакционные («как сделать», «оплатить», «скачать»:
нужен способ по шагам) и информационные («что лучше», «как работает»).
Сверься с базой вопросов, чтобы не писать то же второй раз. Покажи
владельцу 5-10 тем с источником и пометкой «новая» или «обновить».

**Обновить старую статью часто выгоднее, чем написать новую.** На сайте
студии обновление старых гайдов под свежие версии моделей дало рост
показов в разы за несколько недель, новые статьи такого не дали.

### 2. Синопсис с тремя углами и согласование

Шаблон `templates/synopsis.md`, текстом в чат, не файлом в репозитории:
правка на этом этапе стоит минуту. Внутри запрос и источник, три угла
на выбор под номерами, чем лучше текущей выдачи (открой первую страницу
и посмотри, чего там нет), план разделов, что НЕ знаем.

Владелец отвечает одной фразой: «угол 2, ок». Пока согласования нет, ни
обложки, ни текста.

### 3. Факты с источником и датой

Шаблон `templates/facts.md`: одна строка на факт, значение, ссылка на
официальную страницу, дата сверки, где факт стоит. Источник только
первичный: страница тарифов, справка, заметки о выпуске. Сторонний обзор
однажды описывал закрытый сервис как рабочий.

Начни с самого рискованного факта, на котором держится угол. Не
подтвердился: меняй угол, а не подгоняй текст. Неподтверждённое уходит в
раздел «Не подтверждено» и в текст не идёт.

### 4. Обложка

Только после согласования синопсиса, через `aivfx-cover` и `aivfx-look`.
2-3 варианта с разными композициями показать владельцу под номерами до
вставки в проект. Сверь с уже опубликованными обложками: однотипные кадры
подряд делают блог однообразным.

### 5. Текст волнами

Волны: ядро (ответ и главный раздел), потом остальные разделы и FAQ,
потом вторая языковая версия и перелинковка. Два-три круга правок это
норма.

Если статей несколько, раздай субагентам:
- каждый пишет ровно свои файлы (статья RU и EN) во временную папку и не
  трогает репозиторий, тогда агенты не конфликтуют;
- каждый получает синопсис и `facts.md` и отчитывается, в чём не уверен;
  непроверяемые цифры выкидывает сам;
- дирижёр проверяет каждый файл скриптами и глазами и вставляет в данные
  сайта сам.

Подписи к картинкам агент без картинки пишет вслепую по имени файла. Дай
ему описание готового кадра или перепиши подписи сам, глядя на кадр.

### 6. Проверки

```bash
python3 scripts/check_article.py статья.md
python3 scripts/check_text.py статья.md
python3 scripts/check_freshness.py папка_статей/ versions.json
```

Все три должны дать код 0 по всем языковым версиям. Если блог хранит
статьи не в markdown, выгрузи текст в формат проверялки или напиши свою по
этому образцу: главное, чтобы проверка была машинной. Подробно о каждой
ниже, в разделе «Скрипты».

Любую новую проверку проверь подложенной ошибкой: испорти файл нарочно и
убедись, что скрипт падает. Тихая проверка выглядит как «всё чисто».
Останавливайся по качеству находок: две проверки подряд без смысловых
находок значит стоп (однажды было одиннадцать прогонов, хватило бы четырёх).

### 7. Правки владельца списком

Правки приходят голосом, скринами, кусками в чат. Разбери и подтверди
пронумерованным списком («понял так: 1... 2... 3...»), после правки
отметь в том же списке, что сделано.

### 8. Выкат пачкой

- Только по прямому слову: «выкатывай», «деплой». «Ок» и «давай» это не
  команда.
- Одной пачкой со всем накопленным: каждый выкат может стоить денег.
- Готовую пачку запиши в `DEPLOY-QUEUE.md` проекта по шаблону
  `templates/deploy-queue-entry.md` и не спрашивай «выкатывать?» после
  каждой правки.
- После выката проверь живую версию: страница открывается, правка на
  месте, счётчик считает (`aivfx-track`).

### 9. Индексация

- **Google:** запрос индексации через Search Console в браузере владельца,
  строка «Проверка всех URL», потом «Запросить индексирование». API для
  этого нет. Лимит порядка десятка адресов в сутки на ресурс (на октябрь
  2026, перепроверь), поэтому первыми отправляй новые статьи.
- **Bing и Яндекс:** один запрос IndexNow со списком адресов, ключ лежит
  файлом в корне сайта. Ответ 202 значит принято. Отказ одного поисковика
  не всегда значит, что адрес не дошёл: адреса расходятся по общей сети
  IndexNow, смотри счётчик отправленных в его панели.
- Обновлённой статье подними дату изменения в данных и в разметке, иначе
  поиск не узнает об обновлении.

### 10. Замер через неделю

Через неделю `aivfx-track`: показы и клики раздельно, позиции кластера,
цели Метрики, клики по переходнику. Сверь с пунктом «что смотреть» в
очереди выката. Находку запиши в журнал уроков проекта в тот же день.

## Ключевые правила статьи

**Структура:**
1. Заголовок с главным запросом ближе к началу, до 70-80 знаков.
2. Описание до 160 знаков, не повторяет заголовок.
3. Блок «Коротко» сразу после вступления: 3-4 ответа одной строкой
   («Есть ли бесплатный тариф: да, с водяным знаком»).
4. Разделы H2 под формулировки запросов, минимум четыре. Первые 1-2
   предложения раздела отвечают на заголовок прямо.
5. Тарифы и шаги списками и таблицами.
6. Раздел «Частые вопросы», вопросы H3, **каждый кончается на «?»**:
   разметка вопросов собирается только по таким заголовкам.
7. Три и больше внутренних ссылки по смыслу, в тексте.
8. Видимая дата обновления и автор-человек.

Каждый абзац-ответ понятен без соседних: ИИ-ответы поисковиков берут
текст кусками. Не «он стоит», а «тариф Pro стоит».

**Языки.** Английская версия это полный перевод русской со всеми
практическими шагами: живой перевод, все шаги, таблицы и ссылки на месте,
факты сверены в каждой версии отдельным проходом. Урезанная версия на
другом языке хуже, чем никакой. Если версия на другом языке месяцами не
даёт кликов, закрой язык решением владельца, а не урезанием.

**Партнёрская ссылка.** Одна на статью, с раскрытием одной фразой рядом,
`rel="sponsored nofollow"`, через переходник `/go/<партнёр>` из
`aivfx-track`. Адрес в одном файле-реестре, в статье ключ. Не в рейтингах
«лучшее из». Минусы партнёра честно; если нужного через партнёра не
сделать, так и скажи.

**Язык.** Никаких длинных и средних тире: дефис, точка, двоеточие. Без
канцелярита («является», «осуществляет»), штампов («в современном
мире», «давайте разберёмся», «не просто X, а Y»), троек прилагательных,
пустых вступлений и выводов, пафоса, обещаний дохода и выдуманного опыта
(«проверили сотни»). Факт вместо оценки, короткая фраза, «я» вместо «мы»,
если пишет один человек. Правь минимально и сохраняй голос автора.

**Свежесть.** У каждой цены, лимита и версии дата сверки рядом: «на
октябрь 2026, на странице тарифов». Цены сверяй на официальной странице в
день выката, а не в день написания. Никаких акций «до 28 сентября», «до
конца месяца», «успейте». Нет прошлого года в заголовке. Одна модель во
всех статьях под одной версией. Раз в месяц проход по блогу.

## Скрипты

- `check_article.py статья.md [--min-words 700] [--min-h2 4] [--h1-in-body]`:
  ОШИБКА (код 1) за отсутствие `title` или `description`, описание длиннее
  160, нет FAQ или вопрос без «?», мало H2, длинные тире, пустые ссылки,
  H1 в теле, мало слов. ЗАМЕЧАНИЕ за отсутствие «Коротко», даты, автора,
  мало внутренних ссылок. Формат: markdown с фронтматтером `title`,
  `description`, `updated`, `author`.
- `check_text.py путь [--stoplist свой.txt]`: стоп-лист `stoplist.txt`
  (фраза, `re:` регулярка, совет после ` => `, разделы `## `). Код 1 при
  любой находке. Скрипт находит, решает человек: «уникальный
  идентификатор» законен.
- `check_freshness.py папка versions.json [--today ГГГГ-ММ-ДД]`: старые
  версии рядом с именем своего сервиса, версия новее таблицы, сроки акций,
  прошлый год в заголовках, сводка разных версий одного сервиса. Таблица
  старше `ttl_days` (по умолчанию 45) сама ОШИБКА. Начни с копии
  `versions.example.json`. Каждый новый сервис в таблице проверь подсадкой:
  поставь заведомо большую версию, старые упоминания должны найтись, а
  версии соседей с тем же номером нет.
- `suggest.py "затравка" [--out файл.csv] [--hl en] [--dry-run]`: алфавит
  и вопросительные слова вокруг затравки через публичный эндпойнт подсказок
  Google, пауза не меньше 0,5 секунды. Подсказки Яндекса отличаются, главные
  формулировки сверь в его строке поиска.

Находки свежести читай глазами, автоматом не правь: «безлимит только на
старой версии» это правильный факт, а не протухший.

## Типичные ошибки

- **Картинки до согласования темы.** Обложки рисовались под тему, которую
  потом меняли. Порядок: тема, синопсис, согласование, визуал.
- **Вопрос FAQ без «?».** Два агента из трёх так написали, разметка молча
  не собралась. Теперь это ловит скрипт.
- **Почистил тире, сломал проверку.** Массовая замена прошла по коду
  проверялки. В коде тире только кодами U+2014 и U+2013 (`\u2014`, `\u2013`). Кириллицу не
  правь sed или perl без режима UTF-8: они режут байты букв.
- **Факт по памяти.** Цены подписок отличались от реальных в разы, версия
  модели сменилась за девять дней до публикации. Сверка перед сборкой.
- **Акция с датой.** Протухла через два дня после выката.
- **Регулярка, которая ничего не ловит.** Новая модель не попала в
  таблицу, проверка показывала «всё свежее». Подсадка в обе стороны.
- **Обещанный разбор без пункта.** «Разбор по сервисам» без сервиса, под
  который шёл весь трафик. Сверяй обещания вступления с разделами.
- **Правка только русской версии.** Исправление в английскую само не
  приезжает.
- **Дата из головы.** Часы машины и дата в интерфейсе расходятся на день.
  Дату обновления бери командой `date`, иначе она уедет в будущее.

## Чек-лист перед выкатом

- [ ] Тема из Search Console, Вебмастера или живого вопроса, источник
      записан в базе вопросов.
- [ ] Синопсис согласован одной фразой, правки закрыты списком.
- [ ] `facts.md`: у каждого факта источник и дата, цены сверены сегодня.
- [ ] Обложка выбрана владельцем, подписи по реальному кадру.
- [ ] «Коротко», H2 под запросы, FAQ с «?», 3+ внутренних ссылки.
- [ ] Обе языковые версии полные, факты сверены в каждой.
- [ ] Партнёрская ссылка одна, с раскрытием и `sponsored nofollow`.
- [ ] Три скрипта с кодом 0 по всем версиям.
- [ ] Нет длинных тире, штампов, акций «до числа».
- [ ] Дата обновления поднята, запись в `DEPLOY-QUEUE.md`.
- [ ] Выкат после прямого слова владельца.
- [ ] Индексация: Search Console и IndexNow.
- [ ] Замер через неделю стоит в задачах.

Где ещё публиковать, кроме блога, решает владелец отдельно.

## Что устаревает первым

Цены подписок, номера версий, лимиты бесплатных тарифов, правила
расширенных сниппетов (FAQ-сниппет Google с 2023 года показывает в
основном государственным и медицинским сайтам, разметку всё равно ставь:
её читают ИИ-ответы), лимиты запроса индексации, интерфейсы панелей,
публичный эндпойнт подсказок, сами приметы нейросетевого текста. Пример в
`versions.example.json` это формат, а не справочник. Факты проверены на
октябрь 2026, перепроверь.
